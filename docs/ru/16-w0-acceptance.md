# Приёмка границ W0

**Результат 2026-11-01:** 13 сценариев прошли; 46 тестов в Linux, 39 в Windows и 7 Linux-only пропущены. Принят только описанный профиль.

[English](../en/16-w0-acceptance.md) · [Измерения](../../world/wsl2/evidence/w0-acceptance-2026-11-01.json) · [План](../../planning/world.md) · [ADR-009](../../adr/009-w0-acceptance-scope.md)

## Область проверки

Приёмка относится к последовательному, однопоточному Python-профилю текущего WSL: общий предел 512 MiB/1,25 ядра/128 задач, worker 256 MiB/одно ядро/64 задачи, swap запрещён. Набор системных вызовов, rootfs, read-only вход, ограниченные tmpfs и каналы фиксированы. Второй одновременный запуск отклоняется. Настройки WSL и Docker не меняются.

Это разрешение использовать проверенную границу для следующего этапа разработки, а не утверждение о безопасности любого кода или об отсутствии уязвимостей ядра. Новый путь запуска кандидатов должен использовать ту же границу. Сеть, процессы/потоки, дополнительные пакеты, монтирования или расширение прав требуют изменения политики и повторной приёмки. Сам организм не может разрешать такие изменения.

## Испытания

| Сценарий | Требуемый наблюдаемый результат |
| --- | --- |
| Память | Попытка выделить 320 MiB в worker с лимитом 256 MiB; событие cgroup OOM kill |
| Вывод | Поток stderr больше 1 MiB останавливается; сохранено не больше 1 MiB суммарного вывода |
| Длинная строка | Более 16 KiB без перевода строки → `line_limit` |
| Протокол | Повторяющийся JSON-ключ → `protocol_error` |
| Зависание | Отсутствие heartbeat → остановка через 5 секунд |
| Закрытые каналы | Закрытие stdout/stderr не отменяет надзор; остановка через 5 секунд |
| Полномочия | Запрещены fork/clone3, namespaces, mount, ptrace, BPF и socket; нет capabilities, включён no_new_privs |
| Хранилище и дескрипторы | Срабатывают лимиты tmpfs 16 MiB и 256 дескрипторов |
| Видимость | Проверки UID/GID, файловой системы, сети и очищенного окружения |
| CPU | Загрузка одного ядра: наблюдаются throttling и предел CPU-времени либо настенный таймер |
| Настенный таймер | Heartbeat продолжается при почти простаивающем CPU; остановка через 70 секунд |
| Задачи | Доверенный служебный helper достигает 64 задач в том же worker; ядро отклоняет следующую |
| Смерть контроллера | После SIGKILL контроллера worker пуст; повторный параллельный запуск отклонён |
| Восстановление | После аварии очистка и обычная smoke-проба проходят |

После каждого штатно наблюдаемого случая проверяются пустой worker, удаление собственной cgroup и восстановление списка контроллеров. После смерти контроллера эти проверки выполняет внешний испытатель. Состояние WSL и PID Docker сравниваются до и после всей серии.

Служебный pids-helper — фиксированный доверенный код инфраструктуры, который временно создаёт спящие процессы внутри квот worker. Профиль самого организма по-прежнему запрещает создание процессов: ради испытания лимита seccomp не ослаблялся.

## Воспроизведение и журналы

Код испытаний: [acceptance.py](../../world/wsl2/acceptance.py), фиксированные воздействия: [fault.py](../../world/wsl2/probes/fault.py). Установленная копия принадлежит root; пути или код пользователя не принимаются. Запуск из PowerShell:

```text
.\world\wsl2\config\run-acceptance.ps1
```

Общий внешний тайм-аут — 200 секунд, отдельного запуска — 80 секунд; проверка свободной памяти Windows требует минимум 2 GiB. Ожидаемая длительность всей серии — около 160 секунд из-за двух независимых 70-секундных испытаний.

Журналы сохраняются в `/var/lib/pe-world/runs`, сводки — в `/var/lib/pe-world/acceptance-*.json`. Входы, политика и исполняемые компоненты имеют SHA-256 в отчёте. При заполнении активного журнала запуск отклоняется; оператор может сохранить прежние файлы в `runs/history`, без удаления и в пределах общего бюджета 32 MiB. Лимит активных запусков — 16.

Первая серия остановилась на слишком узком ожидании CPU-теста: ядро остановило процесс около 70 секунд раньше контроллера, код возврата 137. Это сохранённый отрицательный результат испытателя. Итоговая серия допускает оба предусмотренных предела CPU-пробы и отдельно проверяет настенный таймер на другом процессе.

## Граница следующего этапа

Приёмка среды не означает наличие организма, обучения или эволюции. Следующие задачи — контракт клетки и генома, затем прослеживаемое развёртывание структуры P1-17 и развитие P1-18. Функция должна следовать из сформированных элементов и связей; её нельзя заменить готовым органом в коде среды.

Индивидуальные записи `w0_accepted: false` фиксируют исход отдельной пробы, выполненной до итогового решения. Положительная приёмка находится в сводном `acceptance.accepted`; дашборд дополнительно сверяет хеши и версию ядра.
