# Первое предписанное развитие из генома

[English](../en/18-prescribed-development.md) · [ADR-011](../../adr/011-prescribed-development-v0.md) · [Геном](../../examples/development/text-retention.json) · [Результаты](../../world/wsl2/evidence/development-2026-11-01.json)

## Что проверяется

Первый ограниченный пример должен пройти путь **геном → реальные механизмы и клетки → соединение → выполненная функция**. Исходно есть одна клетка без механизмов и связей. Возможность преобразовать строку и передать её в память должна появиться после структурных изменений.

Это предписанное развитие: сами правила написаны разработчиками и находятся в геноме. Оно не доказывает обучение, самостоятельное открытие композиции или эволюцию. Внутриклеточное хранение в этом примере не является долговременным усвоением; органы и пищеварительный цикл ещё не реализованы.

## Контракт v0

Схема `development-v0` — язык-независимые JSON-данные. Она описывает `initial`, список `genes` и `endpoint`. Python — реализация исполнителя, а не примитив генома. JSON остаётся рабочим кодированием; окончательный нуклеотидный алфавит не выбран.

| Элемент | Контракт |
| --- | --- |
| Начальное состояние | Одна клетка с пустым набором механизмов; ID и бюджет заданы геномом |
| Ген механизма | `kind: mechanism`, программа из существующих PP, один текстовый выход `out` |
| Структурный ген | `kind: development`, упорядоченные правила `when.feedback` → `action` |
| `express` | Выразить указанный ген механизма в существующей клетке |
| `bud` | Создать дочернюю клетку с родителем, отдельной памятью и ограниченным бюджетом |
| `connect` | Соединить `out` одной клетки с `in` другой; циклы и дубли запрещены |
| Условие правила | Фактически наблюдаемый недостаток структуры/доставки; правило срабатывает однократно |
| Выход | Значение, реально доставленное в `endpoint.cell.out`; эталон оценивается вне организма |

Внешние пределы модели: геном 16 KiB, входной текст 4 KiB, до четырёх клеток, восьми механизмов, 16 правил и 16 структурных шагов; программа механизма до восьми PP. Бюджет клетки — не больше 64 исполненных операций за её жизнь. Эти числа не заменяют внешние квоты W0.

Клетка содержит механизмы, собственный экземпляр runtime с памятью, очередь до четырёх сообщений, порты `in/out: text`, состояния `idle/running/stopped` и здоровье. Операции тратят бюджет; исчерпание останавливает клетку с причиной. Транзакционность памяти обеспечивается на уровне отдельного механизма существующим runtime. Регенерация и восстановление клетки не реализованы.

## Структура и обратная связь

У [примера](../../examples/development/text-retention.json) три гена: `clean`, `retain`, `body`. Структурный ген задаёт четыре правила:

1. Источник без механизма → выразить `clean` в `seed`.
2. Целевая клетка отсутствует → создать `memory` как потомка `seed`.
3. Цель без механизма → выразить в ней `retain`.
4. Доставка отсутствует → соединить `seed.out → memory.in`.

`clean` содержит `SENSE → TRANSFORM(strip) → TRANSFORM(lower)`. `retain` содержит `SENSE → STORE → SIGNAL`. Среда не знает, что такое готовый орган нормализации: она исполняет описанные примитивы и правила. После каждого изменения снова исполняется фактически существующая структура.

Каждое событие имеет `seq`, `tick`, хеш генома и связано с исходным журналом. Создание клетки, механизма и связи дополнительно ссылается на ген и правило. В лаборатории видны экземпляры клеток, механизмы, память, расходы шагов, связи и исходные события. Показанное состояние берётся из последнего эксперимента; изменение возраста не используется.

## Запуск и контроли

Из корня репозитория:

```powershell
.\scripts\setup-lab.ps1 -UpdateWorld
.\world\wsl2\config\run-acceptance.ps1
.\scripts\run-development.ps1
.\scripts\start-lab.ps1
```

Исполнитель допускает фиксированный доверенный zipapp с примером и контролями. Путь к произвольному коду или новый геном через CLI пока не принимается. Если установленная среда отличается от отчёта W0, развитие блокируется до повторной приёмки. Фиксированный эксперимент и все изменённые варианты исполняются внутри bwrap/cgroup; обычные unittest проверяют только схему, сборку и допуск.

Испытатель проверяет исходную нефункциональность, итог `hello` для входа `  HeLLo  `, отдельную память `last`, происхождение четырёх изменений, воспроизводимость, дополнительный открытый вход `  NeW DATA\t`, изменение результата после удаления `lower`, отсутствие доставки после удаления связи, остановку по бюджету, отказ неизвестной операции и неизменность генома. Открытый дополнительный вход не является закрытым испытанием композиционности.

Сохраняются сводный результат и последовательность событий. Новая способность здесь означает выполнение предусмотренной геномом структуры, без заявления о её самостоятельном приобретении. Следом нужны контракт входных пакетов, долговременное хранение и самостоятельный поиск механизмов.

## Где сам результат и его код

Результат опыта — сохранённый экземпляр `text-retention`: две клетки, два механизма, одна связь, память `memory.last = "hello"`. Процесс опыта завершился; это не постоянно работающий организм. Программа экземпляра задана геномом и исполняется общим движком. Новое Python-приложение в результате опыта не генерируется.

Вверху лаборатории блок **«Итоговый экземпляр»** показывает вход и результат. «Посмотреть организм» открывает фактическое состояние; «Геном JSON» — программу и правила; «Код исполнителя» и «Код примитивов» — точные исходники из выполненного zipapp. Они доступны при совпадении хеша установленного пакета с журналом. «Скачать паспорт JSON» сохраняет состояние, геном, код, происхождение и результаты проверок. Сам API: `/api/organism`.

Ниже расположен просмотр **записи выполнения**: «Показать развитие», шаги вперёд/назад и ползунок. Состояние каждого кадра восстанавливается из 20 реальных событий; скорость просмотра не является длительностью работы организма. Пояснения показывают, чего ещё не хватает для функции и какое правило меняет структуру. Просмотр не запускает новый опыт. При обновлении файлов интерфейса страница автоматически получает новую версию.

Паспорт имеет схему `organism-snapshot-v0`. Импорт и продолжение работы из него пока не реализованы: это часть будущего P1-14. Повторить фиксированный опыт можно через `run-development.ps1` внутри принятого W0.

**Проверено 2026-11-01:** 10 проверок развивающихся вариантов внутри W0; 20 записанных событий; 53 теста данных/допуска/интерфейса в Linux, 44 в Windows и 9 Linux-only пропущены; отдельно проверены кадры записи в Node. Исходные пробы W0 повторены для нового входа до исполнения развития.
