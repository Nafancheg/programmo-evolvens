# Первый прототип

**Актуальный приоритет:** [первый цикл биодвижка](11-bioengine-and-applications.md). Этот документ описывает существующий скалярный фундамент; самостоятельный поиск, усвоение и клетки ещё предстоит создать.

**Изоляция:** по [ADR-006](../../adr/006-world-before-organism.md) до запуска развивающихся/изменяемых вариантов нужен принятый [мир W0](13-virtual-world.md). Этот прототип в процессе ведущей программы не является такой защитой; его фиксированные примеры и доверенные проверки разработки не подтверждают изоляцию.

[English](../en/09-first-prototype.md) · [Главная](../../README.md) · [To-do фазы 1](../../planning/phase-1.md)

**Дата:** 2026-10-31. Исследовательский последовательный исполнитель на Python, без внешних зависимостей. Поддерживается Python 3.11+, локально проверен Python 3.14. Для начала скопируйте репозиторий и выполните из его корня:

```text
python -m programmo_evolvens --output artifacts/smoke.json
python -m unittest discover -s tests -v
```

Первая команда запускает три генома на одном классе исполнителя, сравнивает выходы с простыми эталонными функциями и завершает работу с ненулевым кодом при несовпадении. Вторая проверяет контракты и отказы. Отчёт содержит все выходы, сигналы, журнал узлов, фактическое время каждого запуска, сведения о среде и SHA-256 файлов. Отчёт создаётся локально; каталог `artifacts/` не включается в Git.

## Что выполняется

| Геном | Вход | Результат |
| --- | --- | --- |
| [anomaly](../../examples/genomes/anomaly.json) | Пять числовых наблюдений, включая порог 75 | `normal` при ≤75, `anomaly` и сигнал при >75. |
| [normalize](../../examples/genomes/normalize.json) | Четыре JSONL-записи с текстовым полем `name` | Удаление крайних пробелов, нижний регистр, сохранение последнего значения и сигнал. Это нормализация одного поля, не полный валидатор файлов. |
| [queue](../../examples/genomes/queue.json) | Пять тактов поступления элементов | Размер порции 4 при глубине >3, иначе 1; ограничение 1–4; `ACT` удаляет элементы из очереди FIFO в памяти. Сравниваются число, порядок обработанных элементов и остаток. |

Восемь PP определены в [runtime.py](../../programmo_evolvens/runtime.py), сценарии и разрешённый адаптер очереди — в [demo.py](../../programmo_evolvens/demo.py). Адаптер `queue_take` только забирает объявленное число элементов; политику выбора порции задаёт геном. `TRANSFORM` пока знает только операции `strip` и `lower`. Исполнитель не содержит ветвей по имени генома; эталонные функции находятся в демонстрационном оценщике.

## Рабочий формат JSON v0

Геном содержит `schema_version: 0`, `id`, упорядоченные `steps` и `outputs`. Каждый шаг содержит `id`, `pp`, `version: 1`, `inputs`, `params`. Привязка входа — ровно один объект `{"literal": ...}` или `{"ref": "предыдущий_id"}`. Типы пока только `number` (конечное число), `text`, `bool`. Массивы и объекты не являются значениями портов в v0.

Полный пример структуры смотрите в файлах геномов. Ссылки вперёд, циклы, повторяющиеся ID, неизвестные поля/операции/версии, несовместимые типы и отсутствующие выходы отклоняются до исполнения. Все `SENSE` проверяются на наличие и тип наблюдений до первого эффекта. Это линейное представление ациклического графа, ещё не полная модель нескольких генов, клеток и органов. Схема экспериментальная: [ADR-002](../../adr/002-first-executor.md).

| PP | Контракт v1 |
| --- | --- |
| `SENSE` | `params.source/type`; возвращает типизированное наблюдение. Источник предоставляет ведущая программа. |
| `COMPARE` | Числа `left/right`; `operator`: `gt`, `ge`, `lt`, `le`, `eq`; результат `bool`. |
| `TRANSFORM` | Текст `value`; операция `strip` или `lower`; результат `text`. |
| `DECIDE` | `condition: bool`, `if_true/if_false` одного типа; возвращает выбранное значение. Ветви не являются ленивым исполнением узлов. |
| `ACT` | `value` типа, объявленного адаптером; `params.target` должен быть разрешён ведущей программой. Выход проверяется по контракту адаптера. |
| `STORE` | `params.mode/key/type`; `write` принимает `value`, `read` не имеет входов. Отсутствующий ключ или неверный тип — ошибка. Хранение только в памяти объекта Runtime. |
| `SIGNAL` | `value` любого типа порта, `when: bool`; при true добавляет событие в локальный список `channel`; всегда возвращает `value`. Сетевой доставки нет. |
| `REGULATE` | Число `value`, `params.key/min/max`; ограничивает значение диапазоном и сохраняет настройку. Диапазон генома должен входить в разрешённый ведущей программой диапазон. |

## Пределы и оставшиеся задачи

По умолчанию ведущая программа допускает до 64 шагов и 65 536 байт JSON-полезной нагрузки. Проверяется размер генома, наблюдений и совокупности вычисленных значений/состояния/сигналов. Это логические ограничения уже загруженных данных, а не квота памяти процесса или защита от зависания доверенного адаптера. Жёсткие тайм-ауты, изоляция, суммарные квоты всех клеток и параллелизм остаются в P2/P1-07.

`STORE` и регуляция фиксируются только после успешного запуска. При ошибке шага `RunError.trace` содержит журнал до отказа. Уже выполненный внешний `ACT` не откатывается автоматически, поэтому повторы требуют решения ведущей программы; автоматических повторов нет. Доверенные адаптеры исполняются как обычный код ведущей программы. Нельзя считать этот прототип средством безопасного исполнения произвольного кода.

Журнал и длительности наблюдаемы, но данные примеров открытые и маленькие. Проверки не подтверждают производительность, достаточность 8–12 PP или общий эксперимент из раздела о геноме. Нет обучения, Genesis, наследования между поколениями и полноценной клеточной модели. P1-05/06 остаются открытыми: нужны полноценный E0, ресурсы, заранее объявленные пороги, отложенные данные и независимый оценщик. Идеи развития сохранены в [реестре](../../planning/ideas.md).
